## Configuration and rollback

NixOS uses PipeWire/WirePlumber, so raw ALSA state persistence keeps the upstream NixOS policy instead of enabling a second state manager. The owner-aware `alsactl` is installed and also applies if an administrator enables `hardware.alsa.enablePersistence`.

The defaults can be disabled independently with `aurora.audio.skipLockedControls`, `aurora.audio.initrdSequencer`, `aurora.systemFixes.malcontentSignal`, `aurora.flatpak.enable` and `aurora.fexMesa.enable`. Existing explicit `FLATPAK_GL_DRIVERS` and `FEX_ROOTFS` values win. A custom Flatpak package must expose its Mesa `commit` and contain both validated branches.

Disabling Flatpak integration stops its service, unpins and removes its system extensions, removes its local remote if it still belongs to that generation, and removes only unchanged Aurora override keys. Administrator replacements and per-user installations remain intact. Selecting an earlier NixOS generation restores its repository and source pin. Unsupported runtime branches continue using GL.default through the same merged paths.

FEX guest distribution files are local state, as on Fedora. The default lower rootfs path is `/var/lib/aurora/fex/rootfs`; set `aurora.fexMesa.rootfs` to an existing unpacked distribution rootfs. Guest drivers use `/usr/lib64` for x86_64 and `/usr/lib` for i686, as Fedora's provider does. The read-only provider is mounted at `/var/lib/aurora/fex/mesa-rootfs`. It is used only when mounted, and the service skips a missing rootfs. Images carry the two guest driver builds but do not download a guest distribution or replace a user's chosen rootfs.

## Checks

```sh
python3 -m unittest discover -s tests
nix flake check
nix build --no-link .#alsa-utils .#audio .#ucm .#mesa .#fex-mesa .#flatpak-gl .#kernel .#avd-fw
```

For a new, unpublished guest pin, dispatch `checks.yml` on the image commit before `images.yml`. A manual run with `packages="alsa-utils audio ucm aura kernel mesa fex-mesa flatpak-gl avd-fw"` supplies all changed hardware payloads without rebuilding them in each image job. Image imports check source ancestry, the existing repository/workflow/event/success gates, artifact digests, GitHub provenance attestations, exact current derivation/output identities and every NAR. An ancestor build is reused only while the component's derivation and complete output set remain identical. The import is local to the image build; signed cache publication still requires its existing main-branch and merge gates. Routine images can use the already published signed guest output, while native outputs retain ordinary signed substitution or source builds.

Source builds of the GL extensions require Nix's `uid-range` capability (`auto-allocate-uids` and cgroups enabled on the builder). CI verifies nested user/network namespaces before fetching the SDKs. The outer Nix sandbox stays enabled; installed systems consuming the signed cache do not need to build these SDKs themselves.

The SDK fetch retains the public Flathub origin and TLS verification. A restricted curl-backed object adapter handles an HTTP-client incompatibility observed in CI; OSTree validates the complete graph against its pinned commit, and the Nix fixed-output hash locks the repository. The Mesa builds themselves run offline.

`checks.aarch64-linux.fedora-parity` evaluates all three installer configurations. `scripts/build-image` also runs `scripts/check-parity.py` inside the finished root: it checks package source stamps, both Flatpak branches, both FEX architectures, six AVD variants and the actual initrd. These software gates do not establish a successful physical boot or runtime graphics/audio qualification.
