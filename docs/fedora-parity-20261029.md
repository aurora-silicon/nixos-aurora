## Configuration and rollback

The defaults can be disabled independently with `aurora.audio.skipLockedControls`, `aurora.audio.initrdSequencer`, `aurora.systemFixes.malcontentSignal`, `aurora.flatpak.enable` and `aurora.fexMesa.enable`. Existing explicit `FLATPAK_GL_DRIVERS` and `FEX_ROOTFS` values win. A custom Flatpak package must expose its Mesa `commit` and contain both validated branches.

Disabling Flatpak integration stops its service, unpins and removes its system extensions, removes its local remote if it still belongs to that generation, and removes only unchanged Aurora override keys. Administrator replacements and per-user installations remain intact. Selecting an earlier NixOS generation restores its repository and source pin. Unsupported runtime branches continue using GL.default through the same merged paths.

FEX guest distribution files are local state, as on Fedora. The default lower rootfs path is `/var/lib/aurora/fex/rootfs`; set `aurora.fexMesa.rootfs` to an existing unpacked distribution rootfs. The read-only provider is mounted at `/var/lib/aurora/fex/mesa-rootfs`. It is used only when mounted, and the service skips a missing rootfs. Images carry the two guest driver builds but do not download a guest distribution or replace a user's chosen rootfs.

## Checks

```sh
python3 -m unittest discover -s tests
nix flake check
nix build --no-link .#alsa-utils .#audio .#ucm .#mesa .#fex-mesa .#flatpak-gl .#kernel .#avd-fw
```

`checks.aarch64-linux.fedora-parity` evaluates all three installer configurations. `scripts/build-image` also runs `scripts/check-parity.py` inside the finished root: it checks package source stamps, both Flatpak branches, both FEX architectures, six AVD variants and the actual initrd. These software gates do not establish a successful physical boot or runtime graphics/audio qualification.
